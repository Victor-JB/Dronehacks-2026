## Failure, disconnect, hang and memory handling

Ordinary nonzero commands, missing tests, skipped/error/failure JUnit cases or forbidden/incomplete isolation evidence fail the build script. Outer deadline is automatic and independent of SSH. Host monitor failure revokes/stops; abrupt monitor loss expires the lease. Failed/no timeout verification prevents build/test launch. Build/graph/cleanup hangs still reach outer TERM600s/KILL605s, assuming normal trusted kernel signaling/scheduling. An unavailable Docker daemon can prevent RPC cleanup/evidence collection, but cannot renew the lease or disable the independent PID1 timer.

Memory is capped at1536MiB, with no additional swap allowance,192 PIDs,one CPU quota and256MiB tmpfs. Host monitor aborts at90% sandbox memory or any read cgroup OOM/allocation event; it rejects unavailable effective-limit/OOM telemetry before granting build permission. Host available RAM<1GiB and disk<2GiB abort. The sandbox cannot silently restart. No disk or I/O quota is added; disk telemetry and runtime bound are the guards. Monitoring is sampled, not real-time/thermal certification or a guarantee against kernel/daemon failure. Logs may end abruptly on KILL/OOM; workspace/Docker evidence is retained, not auto-removed, and omissions must be disclosed.
